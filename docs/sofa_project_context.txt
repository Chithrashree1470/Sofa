============================================================ 5. DESIGN
DECISIONS ============================================================

Coordinate scaling: - Never scale coordinates directly. - Scale
dimensions. - Keep centre fixed. - Recompute min/max from: center ±
dimension/2

Reason: Preserves placement while dimensions change.

Scaling architecture: - One scaler per component. - Generic verification
framework. - Component-specific engineering checks.

============================================================ 7.
IMPORTANT DISCOVERY
============================================================

Fusion L/W/H are LOCAL CAD AXES.

They are NOT guaranteed to represent: - Length - Depth - Height

Each body can have a different axis mapping.

Example:

seat_top L = sofa length W = cushion thickness H = seat depth

seat_front L = sofa length W = front height H = panel thickness

Future components must determine axis mapping before scaling.

============================================================ 10. CURRENT
FUSION ISSUE
============================================================

Fusion reconstruction currently produces incorrectly oriented parts.

Reason: Builder assumes every body uses:

X = L Y = W Z = H

This assumption is false because different bodies use different local
axes.

Coordinates are temporarily ignored until orientation handling is
redesigned.

============================================================ 12. LESSONS
LEARNED ============================================================

-   Never assume Fusion L/W/H correspond to physical dimensions.
-   Separate scaling logic from engineering validation.
-   Build reusable component scalers.
-   Keep verification generic.
